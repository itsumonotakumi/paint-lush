# ペイントラッシュ！ 要件定義書

Nov 5, 2026 · @いつもの匠

## 1. 概要・目的・前提

ブラウザだけで遊べる「インクで陣地を塗り合う3Dチーム対戦TPS」を作り、GitHub Pagesで公開する。DBもサーバーも持たない静的サイト構成とする。

**目的**

- PC・スマホ・タブレットのどれでも、URLを開くだけで即プレイできる
- ゲームパッドでもタッチでもキーボード＋マウスでも快適に操作できる
- BGMと効果音で「テンションが上がる」体験を最優先にする

**IP方針（必須）**

ゲームの仕組み（塗り・潜伏・陣取り）はジャンルとして参考にしてよい。一方で、既存作品や他社の名称・キャラクター・ロゴ・ステージ・武器デザイン・楽曲・効果音は一切使わない。

- タイトル、キャラ、武器名、ステージ名はすべてオリジナルにする
- 既存作品の名称は公開物（タイトル、README、リポジトリ名、SNS告知、本書を含むドキュメント）に使わない
- 素材はすべて自作、またはライセンスを確認したフリー素材・AI生成素材のみ使う。素材ごとに出典とライセンスを CREDITS.md に記録する
- 公開リポジトリにするため、これは公開前のチェック項目にも入れる

## 2. 対象環境・入力デバイス

全5環境でゲームパッド操作を標準サポートし、ゲームパッドがない端末ではタッチまたはキーボード＋マウスで遊べるようにする。

| 環境 | ブラウザ | 主な入力 | 注意点 |
| --- | --- | --- | --- |
| PC（Windows） | Chrome / Edge / Firefox | キーボード＋マウス、ゲームパッド | マウスはPointer Lockで視点操作 |
| Mac | Safari / Chrome | キーボード＋マウス、ゲームパッド | Safariのゲームパッド認識を実機確認 |
| iOS（iPhone） | Safari | タッチ、ゲームパッド（DualSense / Xbox / MFi） | 全画面APIが制限されるため、ホーム画面追加（PWA）で全画面化 |
| iPadOS | Safari | タッチ、ゲームパッド、キーボード | ジャイロ使用時は許可ダイアログが必要 |
| Android | Chrome | タッチ、ゲームパッド | 端末性能の幅が大きく、画質の自動調整が必須 |

**入力の要件**

- ゲームパッドはGamepad APIで標準マッピング（Xbox配置）に対応する。接続と切断を自動検知し、ボタン表示もそれに合わせて切り替える
- ジャイロエイム：ゲームパッドのジャイロはブラウザから取れないため、スマホ・タブレット本体のジャイロ（DeviceOrientation）のみ対応する。設定でON/OFFを切り替える
- タッチUIは左：移動スティック、右：視点ドラッグ＋射撃・ジャンプ・潜伏（インクに潜る）・サブ・スペシャルの各ボタンとする
- キー割り当てと感度は設定画面で変更でき、localStorageに保存する
- 振動（Vibration / GamepadHapticActuator）は対応端末のみ有効にする

## 3. ゲームモード・ルール

MVPは「4対4の塗り合い（CPU戦）」1本に絞る。サーバーなしで成立し、1人でもすぐ遊べるからだ。

| モード | 内容 | 人数 | フェーズ |
| --- | --- | --- | --- |
| ナワバリ型（塗り面積勝負） | 3分間で塗った面積が多いチームの勝ち | 自分＋CPU7体（4対4） | MVP |
| 練習場 | 的当て・武器試し撃ち・操作チュートリアル | 1人 | MVP |
| ローカル対戦 | 1台の画面分割で2人まで（PC・iPad向け） | 2人＋CPU | フェーズ2 |
| オンライン対戦（P2P） | ルームコードで友達と対戦。WebRTCで直接通信 | 2〜8人 | 初版では対象外 |
| エリア確保型 | 指定エリアを塗って確保しカウントを進める | 4対4 | フェーズ2 |

**ルールの要件**

- 試合時間は3分（設定で1〜5分に変更可）。残り1分でBGMを切り替え、残り10秒でカウントダウン演出を入れる
- 勝敗は塗り面積の割合（%）で判定する。結果画面では塗り比率バー、個人の塗りポイント、キル数を表示する
- やられたらリスポーン地点から復帰する（復帰まで約5秒）
- CPUは難易度を3段階（やさしい／ふつう／つよい）用意する。行動は「塗り優先」「敵を追う」「味方を援護」の切り替えで作る
- 戦績やランクは保存しない。保存するのは設定と、ローカルの累計記録（localStorage）だけにする

## 4. ゲームシステム

面白さの核は「撃てば床が塗れる」「自分の色のインクに潜ると速く動けて回復する」の2点。ここの気持ちよさを最初に作り込む。

**塗り**

- 床と壁にインクを塗れる。各面に低解像度の塗りテクスチャを持ち、着弾点にスプラット（飛び散り形状）を描き込む
- 塗り面積は各面の塗りマップを集計して算出する。毎フレームではなく0.5秒ごとに計算し、負荷を抑える
- 敵インクの上では移動が遅くなり、少しずつダメージを受ける

**移動・潜伏**

- ヒト形態：歩く・ジャンプ・撃つ
- 潜伏形態：自インクの中を高速移動し、インク残量が回復する。壁の自インクは登れる
- 形態の切り替えは1ボタン、0.1秒以内で反応させる

**インク残量**

- 射撃・サブウェポンでインクを消費し、潜伏中に急速回復する。残量はキャラ背面のタンク表示と画面UIで示す

**武器（MVPは3種）**

| 種別 | 特徴 | 射程 | 連射 |
| --- | --- | --- | --- |
| 標準ブラスター（仮） | 万能型。初心者向け | 中 | 速い |
| ローラー型（仮） | 地面を転がして太く塗る。近接で一撃 | 近 | なし（押し続け） |
| チャージ型（仮） | 溜めて撃つ長射程。一直線に塗る | 長 | 遅い |

- サブウェポンは「投げるインク爆弾」1種、スペシャルは「一定時間の超強化」1種から始める。スペシャルは塗りでゲージを溜めて発動する
- 武器・キャラの見た目と名前はオリジナルで作る

**キャラ・ステージ**

- キャラはオリジナル造形。チームカラーは毎試合ランダムな補色ペア（色覚サポート用の配色も用意）
- ステージはMVPで2面。高低差・塗れる壁・中央の取り合い地点を必ず入れる

**演出（テンション要件）**

- 撃破時はヒットストップ、画面揺れ、インクの大爆発エフェクトを入れる
- 塗り音・着弾音は塗った量に応じて音量と音程を変え、塗っている手応えを出す
- 試合開始カウント、残り1分、勝利と敗北のジングルを用意する

## 5. サウンド要件（BGM・SE）

BGMはテンポ速め（BPM150〜175）のロック・パンク・エレクトロ系で、すべてオリジナルまたは商用利用可の素材を使う。既存曲の「耳コピ」や「風」の寄せすぎは避ける。

**BGM（MVPで5曲）**

| 場面 | 曲調 | 長さ |
| --- | --- | --- |
| タイトル・ロビー | 明るいポップロック | 1〜2分ループ |
| 試合中（通常） | 疾走感のあるパンク／エレクトロ | 2〜3分ループ |
| 試合中（残り1分） | テンポと音圧を上げた切迫系 | 1分ループ |
| 勝利 | 短いファンファーレ＋余韻 | 10〜20秒 |
| 敗北 | 軽く悔しいジングル | 10〜20秒 |

**効果音（MVPで約30種）**

- 射撃（武器ごと）、着弾、塗り、潜伏の出入り、潜伏中の移動音、ジャンプ・着地
- 被ダメージ、撃破、やられ、リスポーン、スペシャルのゲージ満タン・発動
- UI（カーソル、決定、キャンセル）、カウントダウン、試合開始と終了のホイッスル

**技術要件**

- Web Audio APIで鳴らす。iOSとAndroidは最初のタップで音声を有効化する（「タップしてスタート」画面を置く）
- BGM・SE・ボイスの音量を個別に設定し、localStorageに保存する
- 同時発音数の上限を設ける（目安16音）。近くの音を優先し、距離で減衰させる
- 形式は軽量なOGG（Opus）を基本とし、Safari向けにAAC（m4a）も用意する
- 素材の入手：BGMは自作・作曲依頼・商用可のAI作曲サービスから選ぶ。SEはjsfxr等の生成ツールや商用可の素材サイトを使う。各ライセンスはCREDITS.mdに記録する

## 6. 非機能要件・技術構成

構成はTypeScript＋Three.js＋Vite。ビルド成果物をGitHub ActionsでGitHub Pagesへ自動デプロイする。

**性能目標**

| 項目 | 目標値 |
| --- | --- |
| フレームレート（PC・Mac・iPad） | 60fps |
| フレームレート（スマホ中位機） | 30fps以上（60fps目標） |
| 初回ロードの転送量 | 20MB以下（音声は試合開始時に遅延読み込み） |
| 初回表示までの時間 | 4G回線で5秒以内にタイトル画面 |
| 入力遅延 | 入力から画面反映まで100ms以内 |

**技術スタック（案）**

| 役割 | 採用候補 | 理由 |
| --- | --- | --- |
| 3D描画 | Three.js（WebGL2） | 対応端末が広い。WebGPUは使える端末だけ任意で使う |
| 物理・当たり判定 | 自前の簡易判定、または Rapier（WASM） | 必要なのはキャラ移動と弾の判定だけで足りる |
| 塗り処理 | レンダーターゲットへのスプラット描画（GPU） | CPU処理では塗り面積の更新が重くなる |
| 音声 | Web Audio API（Howler.js も可） | iOSの音声制約に対応しやすい |
| 入力 | Gamepad API、Pointer Events、Pointer Lock | 全入力を1つの入力レイヤーにまとめる |
| 保存 | localStorage | DBを使わない方針どおり |
| PWA | Service Worker＋manifest | iOSの全画面化とオフラインプレイ |
| デプロイ | GitHub Actions → GitHub Pages | push だけで公開まで完了する |

**その他の要件**

- 画質は自動調整する（描画解像度、影、パーティクル数）。設定画面でも低・中・高を選べるようにする
- 縦画面の場合は「横向きにしてください」と表示する
- GitHub Pagesの制限（サイト全体1GB、1ファイル100MB、帯域は月100GBの目安）に収める
- 外部への通信はしない（P2Pを入れる場合のみシグナリング通信が発生する）。解析タグも入れない
- リポジトリは公開とし、コードのライセンス（MIT等）と素材のライセンスを分けて明記する

## 7. 名称・世界観（決定）

タイトルは「ペイントラッシュ！（PAINT RUSH!）」に決定した（2026-11-05）。登場キャラは全員忍者で、「ペンキに溶けて潜る忍術を使う若き忍たちが、ネオンの城下町を塗り合う」世界観とする。

**世界観・キャラ**

| 項目 | 名称 | 説明 |
| --- | --- | --- |
| キャラ | 彩忍（いろにん） | ペンキ忍術を使う若い忍者。全員が覆面・忍装束で、装束の差し色がチームカラーになる |
| チーム | ◯◯の里（例：紅蓮の里／蒼雷の里） | 試合ごとにチームカラーに合わせて里の名前が変わる |
| ヒト形態 | 構え（カマエ） | 立って撃てる状態 |
| 潜伏形態 | 染遁（せんとん）の術 | 自分の色のペンキに溶けて高速移動し、ペンキを補充する。自色の壁は忍者らしく駆け上がれる |
| ペンキ残量 | 瓢箪（ひょうたん） | 腰に下げたペンキ瓢箪。残量が見た目でわかる |
| リスポーン地点 | 隠れ家 | 各チームの出撃地点 |

**武器・サブ・スペシャル**

| 種別 | 名称 | 説明 |
| --- | --- | --- |
| 標準ブラスター | 彩手裏剣（いろしゅりけん） | ペンキ手裏剣を連射する万能型 |
| ローラー型 | 大筆（おおふで） | 巨大な筆で地面を塗り広げ、振り抜いて近接攻撃 |
| チャージ型 | 長吹き矢（ながふきや） | 息を溜めて一直線に撃ち抜く長射程 |
| サブ（投擲爆弾） | 彩煙玉（さいえんだま） | 投げると数秒後に破裂し、周囲を塗る |
| スペシャル（超強化） | 奥義・百花繚乱 | 一定時間、射撃速度と塗りが強化され、専用BGMが流れる |

**モード・ステージ**

| 種別 | 名称 |
| --- | --- |
| 塗り面積勝負 | 色取り合戦（いろどりがっせん） |
| エリア確保型 | 陣取り |
| 練習場 | 修行場 |
| ステージ1（MVP） | ネオン城下町（高低差のある商店街と瓦屋根） |
| ステージ2（MVP） | からくり港（積まれたコンテナと可動クレーン） |

**演出への反映**

- 試合開始の掛け声は「いざ、参る！」、勝利は「勝鬨（かちどき）」、残り1分は「時は来た！」などの和風コールを入れる
- BGMはロック・エレクトロに和楽器（三味線・和太鼓・尺八）を混ぜた「和ロック」路線にする
- 撃破時のエフェクトに煙と木の葉を加え、忍者らしさを出す
- 非売品のため、商標調査は行わない（2026-11-05判断）。ただし元作品の名称・素材を使わない方針は変えない

## 8. 開発フェーズ・未決事項

最初に「1ステージで撃って塗って潜る」の手触りを作り、それが面白いと確認できてから対戦とコンテンツを足していく。

1. **プロトタイプ**：1ステージ、1武器、塗りと潜伏、ゲームパッドとキーボードの操作。ここで手触りを判断する
2. **MVP**：4対4のCPU戦、武器3種、ステージ2面、タッチUI、BGM5曲とSE約30種、PWA化、GitHub Pagesで公開
3. **フェーズ2**：エリア確保型、ローカル画面分割、武器とステージの追加、ジャイロエイム調整
4. **フェーズ3**：オンラインP2P対戦（初版では対象外。初版公開後に改めて判断）

**未決事項**

- [ ] 【決定 2026-11-05：初版ではやらない】オンライン対戦はやるか。GitHub Pagesだけでは接続の仲介（シグナリング）ができない。外部の無料シグナリング（PeerJS等）に頼るか、Cloudflare Workers等で自前で立てるかの判断が必要。8人P2Pは回線品質の差で同期が崩れやすく、難易度は高い
- [ ] 【決定 2026-11-05】タイトル「ペイントラッシュ！」、全員忍者の世界観（7章）
- [ ] BGMの調達方法：自作、作曲依頼、AI作曲のどれにするか
- [ ] 3Dモデルの調達方法：自作（Blender）、AI生成、フリー素材のどれにするか
- [ ] 公開範囲：一般公開か、身内限定のURL共有か
- [ ] 最低動作保証の端末（例：iPhone 12以降、Android中位機）
